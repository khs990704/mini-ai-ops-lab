- 함수와 중요 동작의 목적을 한글 docstring과 주석으로 설명했다.
- 실제 파일이 생긴 `src/`에서 더 이상 필요하지 않은 `.gitkeep`을 제거했다.
- README에 학습 명령, 예상 출력, 현재는 log와 artifact를 생성하지 않는다는 범위를 기록했다.

4. `main()`과 Python 진입점을 추가한 뒤 같은 명령으로 JSON이 출력됨을 검증했다.
5. README에 실제 실행 방법과 예상 결과를 반영하고 문서의 명령을 다시 검증했다.
6. 전체 구현과 Q&A를 검수한 뒤 MLOps 위키와 Day 2 작업 기록을 최종화했다.

## 코드 및 설정 의도

- `load_and_split_data()`는 dataset 로딩과 분리를 담당하여 학습 함수가 모델 동작에 집중하게 한다.
- `TEST_SIZE = 0.2`는 전체 150개 중 30개를 검증에 사용한다는 기준을 한곳에 표시한다.
- `RANDOM_STATE = 42`는 실행마다 같은 데이터 분할을 사용해 결과를 재현할 수 있게 한다.
- `stratify=dataset.target`은 세 Iris 품종의 비율을 학습·검증 데이터에 비슷하게 유지한다.
- `train_model()`은 모델과 metrics를 함께 반환하여 Day 3에서 같은 model 객체를 artifact로 저장할 수 있게 한다.
- 학습에 사용하지 않은 검증 데이터로 accuracy를 계산하여 새 데이터에 대한 분류 결과를 확인한다.
- `main()`과 `if __name__ == "__main__":`는 파일을 직접 실행했을 때만 학습 작업을 시작한다.
- `json.dumps()`는 실행 결과를 다른 프로그램도 읽기 쉬운 JSON 한 줄로 출력한다.

## 실행한 명령과 목적

### `python -c "from src.train_job import load_and_split_data; parts = load_and_split_data(); print([part.shape for part in parts])"`

- 목적: 학습 데이터와 검증 데이터가 80:20으로 올바르게 나뉘는지 확인한다.
- 변경 여부: dataset을 memory에서 읽고 분리한다. log나 artifact는 생성하지 않지만 Python이 무시 대상인 `src/__pycache__/`를 만들 수 있다.
- 실행 결과: `[(120, 4), (30, 4), (120,), (30,)]`이 출력됐다.
- 성공 기준: feature와 target이 각각 학습용 120개, 검증용 30개로 출력되고 exit code 0으로 끝난다.

### `python -c "from src.train_job import train_model; model, metrics = train_model(); print(metrics)"`

- 목적: CLI를 연결하기 전에 모델 학습과 metric 계산 함수가 정상 동작하는지 확인한다.
- 변경 여부: CPU와 memory에서 모델을 학습한다. log나 artifact는 생성하지 않는다.
- 실행 결과: `accuracy`, `train_samples`, `test_samples`가 포함된 dictionary가 출력됐다.
- 성공 기준: accuracy가 $0$과 $1$ 사이이고 sample 수가 120과 30이며 exit code 0으로 끝난다.

### `python src/train_job.py`

- 목적: 명령 한 줄로 전체 기본 학습 작업을 실행하고 결과를 확인한다.
- 변경 여부: dataset 준비, 모델 학습, 검증을 memory에서 수행한다. log나 artifact는 생성하지 않는다.
- 실행 결과: `{"accuracy": 0.9666666666666667, "test_samples": 30, "train_samples": 120}`가 출력됐다.
- 성공 기준: metrics가 JSON 한 줄로 출력되고 exit code 0으로 끝난다.

## 검증 결과

- Iris dataset 150개가 학습용 120개와 검증용 30개로 나뉘었다.
- 모델이 검증 데이터 30개 중 29개를 맞혀 accuracy `0.9666666666666667`을 기록했다.
- CLI 진입점 추가 후 `python src/train_job.py`가 JSON metrics를 출력하고 exit code 0으로 끝났다.
- README에 기록한 명령과 실제 동작이 일치함을 확인했다.
- Day 2 범위에 따라 run log와 model artifact는 생성되지 않았다.

## 직접 확인 방법

사전 조건은 Python과 `requirements.txt`의 의존성이 설치되어 있는 것이다. WSL의 프로젝트 root에서 실행한다.

```bash
cd /home/hskim/project/mini-ai-ops-lab
python src/train_job.py
```

정상 실행되면 다음과 같은 JSON 한 줄이 출력된다.

```json
{"accuracy": 0.9666666666666667, "test_samples": 30, "train_samples": 120}
```

이 명령은 프로젝트 log나 artifact를 생성하지 않는다. Python이 실행 성능을 위해 `src/__pycache__/` bytecode cache를 만들 수 있지만 `.gitignore`에 의해 Git에서는 제외된다.

## Codex Q&A

- 질문: `python src/train_job.py`를 실행했는데 왜 달라지는 것이 없고 출력도 없는가?
  답변: 그 시점에는 함수를 정의하기만 했고 실제로 호출하는 CLI 진입점이 없었다. Python은 함수 정의를 읽은 뒤 종료했기 때문에 출력과 파일 생성이 없었다. `main()`과 `if __name__ == "__main__":`를 추가한 후에는 같은 명령이 학습을 실행하고 JSON metrics를 출력한다.

## 발견한 문제

- 모델 학습 함수까지 구현한 상태에서 `python src/train_job.py`를 직접 실행하면 오류는 없지만 아무 출력도 나타나지 않았다.

## 수정 또는 결정

- 함수 정의와 명령줄 실행을 구분하고, 3단계에서 `main()`과 Python 진입점을 연결했다.
- Day 2는 작은 모델의 실행과 metric 출력에 집중하고 model artifact 저장, run ID, 성공·실패 log는 이후 작업일로 분리했다.
- 학습된 model 객체와 metrics를 함께 반환하여 다음 작업일에 기존 학습 로직을 다시 작성하지 않고 저장 기능을 연결할 수 있게 했다.

## 회고

학습 함수를 만든 뒤 `python src/train_job.py`를 직접 실행하여 출력이 없다는 점을 확인했다. 이 질문을 통해 Python 파일에 함수를 정의하는 것과 파일을 직접 실행했을 때 함수를 호출하는 것은 별개의 단계임을 확인했다. 이후에는 사용자 실행 명령이 있는 기능이라면 내부 함수 검증뿐 아니라 최종 CLI 명령도 직접 확인한다.

## 배운 점

- training job은 데이터 준비, 모델 학습, 평가를 하나의 실행 단위로 묶는다.
- 모델 평가는 학습에 사용하지 않은 검증 데이터로 수행해야 한다.
- accuracy는 전체 예측 중 정답을 맞힌 비율이다.
- `random_state`를 고정하면 같은 데이터 분할과 결과를 재현하기 쉽다.
- `stratify`는 분류 class 비율을 학습·검증 데이터에서 비슷하게 유지한다.
- Python 함수는 정의만으로 실행되지 않으며 CLI 진입점에서 호출해야 한다.
