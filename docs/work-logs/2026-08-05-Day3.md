# Day 3 - 2026-08-05

## 목표

각 학습 실행에 고유한 run ID를 부여하고 학습된 model을 실행별 artifact 경로에 저장한다.

## 완료한 작업

- UTC 생성 시각과 UUID suffix를 조합하는 `generate_run_id()`를 만들었다.
- model을 `artifacts/{run_id}/model.pkl`에 저장하는 `save_model()`을 만들었다.
- 잘못된 run ID 경로와 기존 run 디렉터리 덮어쓰기를 차단했다.
- 기본 학습 CLI에 run ID 생성과 artifact 저장을 연결했다.
- CLI 출력에 `run_id`, `metrics`, `artifact_path`를 함께 포함했다.
- README에 artifact 구조, 확인 명령, Git 제외 규칙, pickle 보안 주의를 기록했다.

## 단계별 진행과 검수

5. 여러 실행이 서로 다른 run ID 디렉터리를 만들고 Git 변경 목록에는 나타나지 않음을 확인했다.
6. README에 현재 동작과 사용자 확인 명령을 반영했다.

## 코드 및 설정 의도

- `src/storage.py`는 run 식별과 artifact 저장 책임을 학습 코드에서 분리한다.
- `generate_run_id()`는 UTC 시각으로 실행 시점을 표현하고 UUID suffix로 같은 시각의 충돌 가능성을 낮춘다.
- `Path(run_id).name != run_id` 검사는 run ID에 경로 구분자가 들어가 artifact root 밖으로 벗어나는 것을 막는다.
- `mkdir(..., exist_ok=False)`는 같은 run ID의 기존 결과를 덮어쓰지 않는다.
- `save_model()`은 저장된 경로를 반환하여 CLI와 이후 run log가 같은 artifact를 가리킬 수 있게 한다.
- `train_job.main()`은 run ID 생성, 학습, 저장, JSON 출력을 하나의 실행 흐름으로 연결한다.
- 파일 직접 실행과 module import에서 모두 `storage`를 찾도록 `__package__`에 따라 import 경로를 선택한다.
- pickle은 Python model 객체 저장에 사용하지만 신뢰할 수 없는 파일을 불러오지 않는다는 보안 경계를 둔다.

## 실행한 명령과 목적

### `python -c "from src.storage import generate_run_id; print(generate_run_id()); print(generate_run_id())"`

- 목적: 연속 호출에서도 서로 다른 run ID가 생성되는지 확인한다.
- 변경 여부: memory에서 문자열만 생성하며 artifact 파일은 만들지 않는다.
- 실행 결과: UTC 시각과 UUID suffix가 포함된 서로 다른 ID 두 개가 출력됐다.
- 성공 기준: 두 문자열이 서로 다르고 `{UTC시각}-{UUIDsuffix}` 형식을 만족하며 exit code 0으로 끝난다.

### `python src/train_job.py`

- 목적: 학습부터 run ID 생성, model 저장, 결과 출력까지 전체 흐름을 실행한다.
- 변경 여부: `artifacts/{run_id}/model.pkl` 파일을 새로 생성한다.
- 실행 결과: accuracy 약 96.67%와 고유 run ID, 실제 artifact 경로가 JSON 한 줄로 출력됐다.
- 성공 기준: exit code 0, JSON의 `run_id`와 경로의 run ID가 일치하고 해당 `model.pkl`이 존재한다.

### `find artifacts -maxdepth 2 -type f -name 'model.pkl' -printf '%p %s bytes\n' | sort`

- 목적: 저장된 model artifact의 실행별 경로와 파일 크기를 확인한다.
- 변경 여부: artifact 목록을 읽기만 하며 파일은 변경하지 않는다.
- 실행 결과: 서로 다른 run ID 디렉터리의 `model.pkl`이 각각 834 bytes로 출력됐다.
- 성공 기준: 하나 이상의 `artifacts/{run_id}/model.pkl` 경로와 0보다 큰 크기가 출력된다.

## 검증 결과

- 연속 생성한 run ID가 서로 달랐다.
- `save_model()`이 run별 디렉터리와 834-byte `model.pkl`을 생성했다.
- `python src/train_job.py`가 `run_id`, `metrics`, `artifact_path`를 JSON으로 출력하고 exit code 0으로 끝났다.
- 같은 명령을 다시 실행했을 때 기존 결과를 덮어쓰지 않고 새 run 디렉터리가 생성됐다.
- 저장된 artifact는 `.gitignore`에 따라 Git 변경 목록에서 제외됐다.
- README에 기록한 두 명령이 실제 동작과 일치했다.

## 직접 확인 방법

Python과 `requirements.txt`의 의존성이 설치된 WSL 환경에서 프로젝트 root로 이동한다.

```bash
cd /home/hskim/project/mini-ai-ops-lab
python src/train_job.py
find artifacts -maxdepth 2 -type f -name 'model.pkl' -printf '%p %s bytes\n' | sort
```

첫 번째 명령은 새 run ID 디렉터리와 `model.pkl`을 생성하고 JSON 결과를 출력한다. 두 번째 명령은 생성된 artifact 경로와 크기를 읽기만 한다. JSON의 `artifact_path`와 `find` 결과가 일치하고 파일 크기가 0보다 크면 정상이다. 학습 명령을 다시 실행하면 새 artifact 디렉터리가 하나 더 생성된다.

## 수정 또는 결정

- run ID에 UTC 시각만 쓰지 않고 UUID suffix를 함께 사용해 충돌 가능성을 낮췄다.
- 같은 run ID의 디렉터리가 이미 있으면 실패하도록 하여 이전 model을 보호했다.
- Day 3에서는 model 저장까지만 구현하고 run 상태 및 JSONL log는 Day 4로 분리했다.
- 생성되는 model artifact는 Git에서 제외하되 경로 구조와 확인 방법은 README에 남겼다.
- pickle은 프로젝트에서 생성한 신뢰할 수 있는 model에만 사용하기로 했다.

## 회고

model을 하나의 고정 파일에 저장하지 않고 run ID별 디렉터리로 분리하여 여러 실행 결과를 함께 보존했다. CLI 출력의 run ID와 artifact 경로를 연결해 어떤 실행이 어느 model을 만들었는지 바로 확인할 수 있게 됐다. 다음 작업에서는 같은 run ID와 경로를 JSONL run log에도 기록해 실행 이력을 파일로 남긴다.

## 배운 점

- run ID는 여러 학습 실행을 서로 구분하고 관련 metric과 artifact를 연결하는 기준이다.
- model artifact는 학습 작업이 끝난 뒤에도 보존하는 결과물이다.
- 실행별 디렉터리는 이전 결과의 덮어쓰기를 방지하고 추적 가능성을 높인다.
- UTC 시각은 환경의 local timezone과 관계없이 실행 시점을 비교하기 좋다.
- pickle은 편리하지만 신뢰할 수 없는 파일을 불러오면 임의 코드 실행 위험이 있다.
- 생성 artifact를 Git에서 제외하는 것과 운영상 백업하는 것은 서로 다른 정책이다.
