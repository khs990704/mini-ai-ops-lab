# Day 13 - 2026-08-16

## 목표

모든 Agent Tool 요청의 상태와 실행 시간을 audit log로 남기고, 제한 시간을 넘긴 handler process를 종료한다.

## 완료한 작업

- `src/audit_logger.py`를 추가해 Tool 요청을 `logs/audit.jsonl`에 JSONL로 누적했다.
- 성공뿐 아니라 미등록 요청, handler 실패와 timeout도 같은 audit schema로 기록했다.
- 시작·종료 UTC 시각, duration, 입력 제공 여부, 제한 시간과 오류 field를 남겼다.
- 원문 입력과 handler 결과 전체를 audit log에서 제외했다.
- `--timeout` CLI option과 30초 기본값을 추가했다.
- Tool handler를 WSL/Linux와 Docker의 별도 process에서 실행하고 pipe로 결과를 받았다.
- 제한 시간 초과 시 child process를 `terminate()`하고 필요하면 `kill()`하도록 했다.
- `success`, `failed`, `timeout`을 구조화된 Tool 결과와 audit record에서 구분했다.
- Local과 Docker에서 정상 실행, 미등록 요청과 timeout을 검증했다.
- README, architecture, failure scenario와 runbook에 운영 절차를 반영했다.

## 코드 및 설정 의도

- `AuditRecord`는 Tool 요청의 이름, 상태, 시각, duration, 입력 제공 여부, 제한 시간과 오류를 고정된 구조로 정의한다.
- `create_audit_record()`는 UTC 시각과 `perf_counter()`를 사용해 시스템 시각 변경에 덜 영향을 받는 요청 시간을 계산한다.
- `append_audit_log()`는 기존 이력을 보존하면서 요청 하나를 JSONL 한 줄로 추가한다.
- 원문 입력 대신 `input_provided`만 기록해 audit log의 민감정보 노출 가능성을 줄였다.
- `run_tool_request()`는 설정 검증부터 handler 결과까지 감싸서 성공·거부·실패·timeout을 반환 전에 기록한다.
- `ToolTimeoutError`는 시간 초과를 일반 실행 실패와 구분한다.
- `ToolHandlerExecutionError`는 child process에서 발생한 원래 오류 종류와 메시지를 부모에게 전달한다.
- `run_handler_in_child()`는 handler 결과 또는 오류를 pipe로 부모 process에 보낸다.
- `execute_handler_with_timeout()`은 지정된 시간만 결과를 기다리고 초과 시 child process를 정리한다.
- `non_negative_float()`는 음수, 무한대와 `NaN` timeout을 Tool 실행 전에 거부한다.
- 중요한 함수, process 정리와 개인정보 판단은 짧은 한글 docstring과 주석으로 설명했다.

## 실행한 명령과 목적

아래 명령은 Day 13 구현 검증을 위해 Codex가 project root에서 실행했다. 사용자가 별도로 실행한 것으로 기록하지 않는다.

### 성공과 거부 Audit Record 생성

```bash
python src/tool_runner.py --tool echo --input "hello"
python src/tool_runner.py --tool unknown
tail -n 2 logs/audit.jsonl
```

- 목적: 허용된 요청과 미등록 요청이 모두 감사 기록으로 남는지 확인한다.
- 변경 여부: 두 Tool 기능은 업무 데이터를 만들지 않지만 `logs/audit.jsonl`에 각각 한 줄을 추가한다.
- 실행 결과: `echo`는 exit code `0`과 `success`, `unknown`은 예상된 exit code `1`과 `failed`, `ToolNotAllowedError`로 기록됐다.
- 성공 기준: 시작·종료 시각, duration, 입력 제공 여부와 오류 field가 두 JSONL record에 모두 존재한다.

### 정상 Timeout 범위 실행

```bash
python src/tool_runner.py --tool echo --input "hello" --timeout 1
```

- 목적: 별도 process의 handler가 제한 시간 안에 정상 결과를 반환하는지 확인한다.
- 변경 여부: audit log 한 줄을 추가하며 다른 업무 데이터는 변경하지 않는다.
- 실행 결과: exit code `0`, `status: success`, duration `0.010689초`, `timeout_seconds: 1.0`이 기록됐다.
- 성공 기준: 문자열 결과와 성공 audit record가 함께 존재한다.

### Tool Timeout 재현

```bash
python src/tool_runner.py --tool run_train_job --timeout 0
```

- 목적: 결과를 기다리지 않고 timeout과 child process 종료 경로를 재현한다.
- 변경 여부: timeout audit record를 추가한다. 쓰기 Tool은 일반적으로 일부 결과를 남길 수 있다.
- 실행 결과: 예상된 exit code `1`, `status: timeout`, `ToolTimeoutError`가 반환됐다.
- 성공 기준: audit record에 `timeout_seconds: 0.0`과 실제 duration이 있고 child 실행이 계속 남지 않는다.

### Timeout의 일부 결과 확인

```bash
wc -l logs/runs.jsonl
find artifacts -maxdepth 2 -type f -name 'model.pkl' | wc -l
```

- 목적: 즉시 timeout 전후로 학습 run과 model 일부 결과가 남았는지 확인한다.
- 변경 여부: run log와 artifact 개수를 읽기만 한다.
- 실행 결과: 첫 검증 전후 run log는 16줄, model은 15개로 변하지 않았다.
- 성공 기준: 검증 시점에는 timeout 요청이 새 run log나 model을 만들지 않는다. 이 결과가 일반적인 rollback을 보장하지는 않는다.

### 잘못된 Timeout 거부

```bash
python src/tool_runner.py --tool echo --input "hello" --timeout -1
```

- 목적: 음수 제한 시간을 Tool 요청 시작 전에 거부하는지 확인한다.
- 변경 여부: Tool process와 audit record를 생성하지 않는다.
- 실행 결과: argparse의 예상된 exit code `2`와 `timeout은 0 이상의 유한한 숫자여야 합니다` 오류가 출력됐다.
- 성공 기준: 잘못된 값이 handler에 전달되지 않는다.

### Local 전체 회귀 검증

```bash
python src/tool_runner.py --tool echo --input "hello" --timeout 1
python src/tool_runner.py --tool list_artifacts --timeout 1
python src/tool_runner.py --tool read_log_summary --timeout 1
python src/tool_runner.py --tool run_train_job --timeout 30
python src/tool_runner.py --tool unknown
python src/tool_runner.py --tool run_train_job --timeout 0
tail -n 6 logs/audit.jsonl
```

- 목적: 네 handler, 미등록 요청, timeout과 audit 상태를 함께 회귀 검증한다.
- 변경 여부: 모든 요청은 audit record를 추가한다. 정상 `run_train_job`은 run log와 model artifact도 생성한다.
- 실행 결과: 네 Tool은 `success`, `unknown`은 `failed`, 즉시 중단 학습은 `timeout`으로 기록됐다.
- 성공 기준: 여섯 요청의 순서, 상태, 제한 시간과 error field가 audit log에 일치한다.

정상 학습은 run ID `20260816T050633281463Z-f5e0baf1`, accuracy `0.9666666666666667`, Tool duration `0.056691초`로 완료됐다. `logs/runs.jsonl`의 record와 `artifacts/20260816T050633281463Z-f5e0baf1/model.pkl` 존재를 확인했다.

### Day 13 Docker Image 생성

```bash
docker build -t mini-ai-ops-lab:day13 .
```

- 목적: Timeout과 Audit Logger가 포함된 재현 가능한 Day 13 실행환경을 만든다.
- 변경 여부: local Docker image와 build cache를 생성하거나 갱신한다.
- 실행 결과: exit code `0`으로 `mini-ai-ops-lab:day13` image가 생성됐다.
- 성공 기준: source와 config 복사, non-root 사용자 준비와 image export가 완료된다.

Docker 기능 검증에서는 project 결과와 섞이지 않도록 일회성 `/tmp` audit 경로를 mount했다. Container의 `echo`는 exit code `0`, `unknown`과 즉시 timeout은 예상된 exit code `1`이었으며 `success`, `failed`, `timeout` 세 audit record가 같은 schema로 저장됐다. 이 임시 경로 준비와 제거 명령은 사용자가 재사용할 project 명령이 아니므로 목록에서 제외했다.

## 검증 결과

- 모든 정상·거부·timeout Tool 요청이 `logs/audit.jsonl`에 한 줄씩 기록됐다.
- Audit record는 요구한 이름, 상태, 시작 시각, 종료 시각, duration과 오류 field를 포함했다.
- 원문 입력은 저장하지 않고 입력 제공 여부만 남겼다.
- 정상 handler는 별도 process에서 제한 시간 안에 결과를 반환했다.
- 즉시 timeout은 child process를 종료하고 exit code `1`과 `ToolTimeoutError`를 반환했다.
- 첫 timeout 검증에서는 run log와 model artifact가 증가하지 않았다.
- 정상 학습은 별도 process에서도 새 run log와 model artifact를 생성했다.
- Local과 Docker의 `success`, `failed`, `timeout` 결과 및 audit schema가 일치했다.
- Python 문법, CLI 도움말과 Git diff 형식 검사가 exit code `0`으로 통과했다.

## 직접 확인 방법

검증은 완료됐으므로 반복 실행은 필수가 아니다. Audit 동작만 직접 확인하려면 dependency가 준비된 WSL의 project root에서 실행한다.

```bash
cd /home/hskim/project/mini-ai-ops-lab
python src/tool_runner.py --tool echo --input "hello" --timeout 1
tail -n 1 logs/audit.jsonl
```

첫 명령은 업무 데이터는 바꾸지 않지만 audit log 한 줄을 추가한다. exit code `0`, `status: success`, `tool_name: echo`, `timeout_seconds: 1.0`이 보이면 성공이다.

Timeout 경로까지 직접 확인할 때만 다음 명령을 실행한다.

```bash
python src/tool_runner.py --tool run_train_job --timeout 0
tail -n 1 logs/audit.jsonl
```

예상 결과는 exit code `1`, `status: timeout`, `ToolTimeoutError`다. 쓰기 Tool timeout은 일부 log나 artifact가 남을 가능성이 있으므로 반복 검증 전후에 관련 결과를 확인한다.

## Codex Q&A

- 질문: Day 13은 시간을 기록하는 Tool을 설정하는 것인가?
  답변: 별도 시간 기록 Tool을 추가하는 것이 아니다. 기존 Tool 요청을 Runner와 Audit Logger가 자동으로 감싸서 시간과 결과를 기록하고 제한 시간도 적용한다.
- 질문: Tool에 제한 시간을 두는 이유는 무엇인가?
  답변: 끝나지 않거나 너무 느린 Tool이 Agent 응답, CPU와 memory를 계속 점유하지 않도록 기다릴 수 있는 상한을 두기 위해서다. Timeout은 이미 발생한 상태 변경을 자동으로 되돌리지 않는다.
- 질문: 기존 Tool들에 대한 기록을 남기는 것인가?
  답변: 맞다. 허용된 실행뿐 아니라 미등록 요청, handler 실패와 timeout도 audit log에 남겨 Agent가 어떤 Tool을 요청했고 결과가 어땠는지 추적한다.

## 발견한 문제

- 같은 process에서 handler를 직접 호출하면 실행이 끝나지 않을 때 Runner가 강제로 중단하기 어렵다.
- 성공 요청만 기록하면 미등록 Tool 시도와 timeout 같은 운영상 중요한 사건을 추적할 수 없다.
- 원문 입력을 audit log에 저장하면 credential이나 민감정보가 기록될 수 있다.
- Timeout은 실행을 멈추지만 이미 만들어진 log, artifact나 외부 상태를 rollback하지 않는다.
- Tool 기능이 완료된 뒤 audit log 쓰기가 실패하면 업무 상태는 바뀌었지만 감사 기록은 남지 않을 수 있다.
- `logs/audit.jsonl`은 아직 동시 append 제어와 rotation이 없다.
- Mount하지 않은 일회성 Container의 audit log는 종료할 때 제거된다.

## 수정 또는 결정

- WSL/Linux와 Docker의 `fork` child process에서 handler를 실행한다.
- Pipe로 결과를 받고 제한 시간 초과 시 `terminate()`, 필요하면 `kill()`로 정리한다.
- 기본 timeout은 30초로 하고 CLI에서 0 이상의 유한한 값만 허용한다.
- 검증용 즉시 timeout은 결정적으로 결과를 기다리지 않는 `--timeout 0`을 사용한다.
- 성공, 일반 실패와 시간 초과를 `success`, `failed`, `timeout`으로 구분한다.
- 원문 입력 대신 `input_provided`만 audit record에 저장한다.
- Tool 결과를 반환하기 전에 audit log를 기록하며, 기록 실패는 운영상 성공으로 간주하지 않는다.
- CLI argument parsing 전에 실패한 요청은 Tool이 시작되지 않았으므로 audit 대상에서 제외한다.
- Docker audit 검증은 project log와 섞이지 않는 임시 mount에서 수행했다.

## 회고

사용자의 질문을 통해 Day 13은 시간을 기록하는 새 Tool을 만드는 작업이 아니라 기존 Tool 전체에 공통 운영 통제를 씌우는 작업이라는 점을 구분했다. 실행 시간을 기록하는 것과 제한 시간이 지나면 실제 process를 중단하는 것은 서로 다른 책임이며, audit log는 성공뿐 아니라 거부와 timeout도 남겨야 추적 가치가 생긴다. Timeout은 rollback이 아니므로 쓰기 Tool의 일부 결과 확인과 원자적 저장은 별도 문제로 남는다.

## 배운 점

- Audit log는 누가 어떤 Tool을 요청했고 결과가 어땠는지 추적하는 운영 이력이다.
- Tool별 시간 측정은 별도 Tool이 아니라 Runner가 공통으로 적용하는 기능이다.
- 별도 process는 제한 시간을 넘긴 실행을 부모 Runner와 분리해 종료할 수 있게 한다.
- `terminate()` 뒤에도 process가 남으면 `kill()` 같은 추가 정리가 필요할 수 있다.
- 단조 시계는 시스템 시각 변경과 관계없이 경과 시간을 측정하는 데 적합하다.
- Timeout은 자원 점유의 상한을 두지만 이미 발생한 상태 변경을 복구하지 않는다.
- Run log는 학습 결과를, audit log는 Tool 요청을 설명하며 목적이 다르다.
- 원문 입력을 기록하지 않는 것은 audit 가능성과 민감정보 최소화 사이의 선택이다.
