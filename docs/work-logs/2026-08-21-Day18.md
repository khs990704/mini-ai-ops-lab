## 실행한 명령과 목적

아래 명령은 Day 18 README 검증을 위해 Codex가 project root에서 실행했다. 사용자가 별도로 실행한 것으로 기록하지 않는다.

### README Section 확인

```bash
rg -n '^## ' README.md
```

- 목적: README의 주요 section과 줄 번호를 확인해 문서 흐름을 검수한다.
- 변경 여부: README를 읽기만 한다.
- 실행 결과: `개요 → 아키텍처 → 주요 기능 → 빠른 시작 → 학습과 실험 추적 → Agent Tool Runner → 로그와 감사 기록 → 장애 대응 → 보안과 백업 → 문서 안내` 순서를 확인했다.
- 성공 기준: 필요한 section이 한 번씩 출력되고 exit code가 `0`이다.
- 대체 방법: ripgrep이 없으면 `grep -n '^## ' README.md`를 사용한다.

### Config 검증과 Quick Start 학습

```bash
python -c "from src.config_loader import load_train_config; print(load_train_config('configs/train.yaml'))"
python src/run_job.py --config configs/train.yaml
python src/list_runs.py --limit 1
```

- 목적: README의 Local Quick Start가 config를 검증하고 새 학습 결과를 기록한 뒤 바로 조회할 수 있는지 확인한다.
- 변경 여부: 첫 명령과 마지막 명령은 읽기 전용이다. `run_job.py`는 run log 한 줄과 성공 시 model artifact 하나를 추가한다.
- 실행 결과: Config 검증과 학습이 성공했다. Run ID `20260821T024802876493Z-dbffecf6`, accuracy `0.9666666666666667`, 834-byte model이 생성됐다.
- 성공 기준: 세 명령이 exit code `0`이고 학습 출력과 최근 run 표에 같은 run ID, `success`와 artifact 경로가 나타난다.

이 실행으로 run log는 21건에서 22건, model은 17개에서 18개로 증가했고 audit log는 당시 12건으로 유지됐다.

### Agent Tool과 Audit 확인

```bash
python src/tool_runner.py --tool echo --input "readme-check" --timeout 1
tail -n 1 logs/audit.jsonl
```

- 목적: README의 Allowlist Tool 실행 결과와 audit record 구조가 실제 동작과 일치하는지 확인한다.
- 변경 여부: `echo`는 업무 data와 model을 바꾸지 않지만 audit log 한 줄을 추가한다. `tail`은 log를 읽기만 한다.
- 실행 결과: Tool과 audit 모두 `status: success`였고 실행 직후 audit log는 12건에서 13건으로 증가했다. Tool 결과에는 `readme-check`가 있었지만 audit에는 원문 대신 `input_provided: true`가 기록됐다.
- 성공 기준: Tool 결과와 마지막 audit record의 `tool_name`, `status`가 일치하고 exit code가 `0`이다.

### CLI와 Docker Metadata 확인

```bash
python src/run_job.py --help
python src/list_runs.py --help
python src/compare_runs.py --help
python src/tool_config_loader.py --help
```

- 목적: README에서 소개한 Python 진입점과 option이 실제 CLI에 존재하고 Docker가 예상 사용자와 작업 directory를 사용하는지 확인한다.
- 변경 여부: 도움말과 image metadata를 읽기만 한다.
- 실행 결과: 다섯 CLI 도움말이 모두 정상 출력됐고 Docker metadata는 `appuser /app`이었다.
- 성공 기준: 모든 Python 명령과 Docker 재확인이 exit code `0`이다.

## 직접 확인 방법

검증은 완료됐으므로 새 run이나 audit record를 다시 만들 필요는 없다. WSL project root에서 다음 명령으로 README 구조와 현재 결과를 읽기만 할 수 있다.

```bash
cd /home/hskim/project/mini-ai-ops-lab
grep -n '^## ' README.md
python src/list_runs.py --limit 1
tail -n 1 logs/audit.jsonl
```

- `grep`은 ripgrep 설치 여부와 관계없이 주요 README section을 출력한다.
- `list_runs.py`는 최근 run을 표로 읽는다.
- `tail`은 최근 audit record를 읽는다.
- 모두 읽기 전용이며 log와 artifact를 추가하지 않는다.
- 성공 기준은 README section, 최근 success run과 JSON audit record가 오류 없이 출력되는 것이다.

실제 Quick Start를 다시 확인하려면 README의 `python src/run_job.py --config configs/train.yaml`을 실행할 수 있다. 이 명령은 새 run log와 model을 추가하므로 결과가 필요한 경우에만 실행한다.

## Codex Q&A

- 질문: Day 18은 전반적인 검수만 하는 날인가?
  답변: 아니다. 주요 결과물은 누적되어 길고 오래된 설명이 남은 README를 기술 독자용 진입 문서로 재작성하는 것이다. 검수는 README의 명령과 설명이 실제 동작과 일치하는지 확인하는 과정이다.
- 질문: `rg`는 어떤 package이며 왜 `sudo apt install ripgrep`이 필요한가?
  답변: `rg`는 ripgrep package가 제공하는 실행 명령이다. 많은 source와 문서를 빠르게 검색하고 기본적으로 `.gitignore`를 존중한다. Project dependency는 아니며 WSL에 없을 때만 system package로 설치한다. 설치하지 않아도 간단한 검색은 `grep`으로 대체할 수 있다.
