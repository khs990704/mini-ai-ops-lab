# 작업 일지

Mini AI Ops Lab의 날짜별 작업 기록 인덱스다. 구현과 검증 결과를 사용자가 검수하고 관련 Q&A를 마친 뒤, 명시적으로 기록을 승인했을 때만 새 작업 일지를 추가한다.

## 파일명 규칙

```text
YYYY-MM-DD-DayN.md
```

예: `2026-08-03-Day1.md`

앞으로 각 기록의 `단계별 진행과 검수`에는 승인된 단계별 구현, 검증, 직접 검수 결과를 남긴다. `코드 및 설정 의도`에는 그날 추가하거나 변경한 주요 파일·함수·설정의 목적과 중요한 주석의 이유를 간단히 설명한다. `실행한 명령과 목적`에는 프로젝트 설치, 실행, 기능 검증, 결과 확인, 장애 대응에 내가 다시 사용할 수 있는 명령만 기록하고 목적, 변경 여부, 실행 결과, 성공 판단 기준을 함께 설명한다. Codex가 파일을 찾거나 문서 서식을 확인하기 위해 사용한 내부 명령은 생략한다. 내부 명령이 프로젝트와 관련된 문제를 발견했다면 명령 사용법 대신 문제와 해결 결과만 간단히 기록한다. 직접 확인할 내용이 있으면 `직접 확인 방법`에 실행 위치, 사전 조건, 복사해 실행할 명령, 예상 결과와 부작용을 작성한다. 코드는 문법을 반복하는 주석 대신 운영 목적이나 이해하기 어려운 판단을 설명하는 짧은 한글 주석과 docstring을 사용한다.

작업 일지는 Codex의 활동 보고서가 아니라 사용자의 프로젝트 수행 및 학습 기록으로 작성한다. 작업, 결정, 검증, 배운 점은 사용자가 프로젝트를 진행한 관점으로 서술하고, Codex의 역할은 필요한 경우 지원으로만 구분한다. `회고`에는 사용자가 실제로 말한 질문, 판단, 수정 의견을 반영하며 사용자가 표현하지 않은 감정이나 경험은 만들어내지 않는다.
